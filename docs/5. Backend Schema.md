# Backend Schema: LifeOps

**Status:** v1.0 — Draft  
**Last Updated:** May 29, 2026

---

## 1. Data Architecture Overview

LifeOps uses a three-tier data architecture:

| Tier | Technology | Purpose | Retention |
|------|-----------|---------|-----------|
| Raw | Google BigQuery | Immutable source-of-truth from Fivetran connectors | 90 days |
| Enriched | Google BigQuery | Transformed, deduplicated, joined across domains | 12 months |
| Search | Elasticsearch | Hybrid semantic + keyword search indices | 12 months |
| Memory | MongoDB Atlas | Permanent evolving user model, preferences, patterns | Indefinite |

## 3. Elasticsearch Indices

```
### Domain Index: events (per domain, per user)
PUT /<user_id>_<domain>/
{
  "mappings": {
    "properties": {
      "user_id":       { "type": "keyword" },
      "domain":        { "type": "keyword" },
      "title":         { "type": "text", "analyzer": "english" },
      "description":   { "type": "text", "analyzer": "english" },
      "timestamp":     { "type": "date" },
      "vector_embedding": {
        "type": "dense_vector",
        "dims": 768,
        "index": true,
        "similarity": "cosine"
      },
      "metadata":      { "type": "object", "enabled": false },
      "sentiment":     { "type": "float" },
      "importance":    { "type": "float" },
      "tags":          { "type": "keyword" }
    }
  }
}

### Cross-Domain Index
PUT /<user_id>_cross_domain/
{
  "mappings": {
    "properties": {
      "user_id":       { "type": "keyword" },
      "domains":       { "type": "keyword" },
      "summary":       { "type": "text", "analyzer": "english" },
      "start_date":    { "type": "date" },
      "end_date":      { "type": "date" },
      "vector_embedding": {
        "type": "dense_vector",
        "dims": 768,
        "index": true,
        "similarity": "cosine"
      },
      "key_metrics":   { "type": "object" },
      "patterns_detected": { "type": "keyword" },
      "relevance_score":   { "type": "float" }
    }
  }
}
```

## 4. MongoDB Schema

```
### Collection: users
{
  _id: ObjectId,
  email: String,
  display_name: String,
  timezone: String,
  wake_time: String,             -- "07:00"
  bed_time: String,              -- "23:00"
  created_at: Date,
  updated_at: Date,
  onboarding_completed: Boolean,
  goals: [
    {
      category: String,          -- "health", "finance", "social", "productivity"
      goal: String,
      target: Mixed,
      priority: Number,          -- 1-5
      active: Boolean
    }
  ],
  preferences: {
    notification_frequency: String,  -- "normal", "reduced", "minimal"
    do_not_disturb_start: String,
    do_not_disturb_end: String,
    briefing_timezone_override: String,
    dietary_restrictions: [String],
    dietary_preferences: [String],
    meeting_limit_per_week: Number,
    subscription_spending_limit_monthly: Number
  },
  data_connectors: [
    {
      connector_id: String,
      source: String,             -- "gmail", "calendar", "plaid", etc.
      status: String,            -- "active", "error", "disconnected"
      connected_at: Date,
      last_sync_at: Date,
      error_message: String
    }
  ]
}

### Collection: user_memories
{
  _id: ObjectId,
  user_id: ObjectId,
  memory_type: String,            -- "pattern", "preference", "fact", "decision", "relationship_event"
  domain: String,
  content: {
    title: String,
    description: String,
    details: Mixed
  },
  vector_embedding: [Number],     -- 768-dim embedding for semantic retrieval
  importance_score: Number,       -- 0-1, computed from access frequency + user feedback
  access_count: Number,
  tags: [String],
  source_trace_ids: [String],     -- links to Arize traces
  created_at: Date,
  last_accessed_at: Date,
  expires_at: Date                -- null for permanent memories
}

### Collection: user_patterns
{
  _id: ObjectId,
  user_id: ObjectId,
  domain: String,
  pattern_type: String,           -- "stress_spiral", "budget_bleed", "exercise_gap", etc.

    trigger_conditions: Mixed,
    typical_sequence: [String],
    duration_days: Number,
    recovery_days: Number
  },
  confidence: Number,             -- 0-1, increases with each recurrence
  occurrences: [
    {
      start_date: Date,
      end_date: Date,
      severity: String,
      outcome: String,
      interventions_attempted: [String],
      intervention_success: Boolean
    }
  ],
  last_occurrence: Date,
  recurrence_count: Number,
  active: Boolean,
  created_at: Date,
  updated_at: Date
}

### Collection: user_relationships
{
  _id: ObjectId,
  user_id: ObjectId,
  contact_email: String,
  contact_name: String,
  relationship_type: String,      -- "family", "friend", "colleague", "partner"
  important_dates: [
    {
      date_type: String,          -- "birthday", "anniversary"
      date: Date,
      recurring: Boolean
    }
  ],
  preferences: {
    dietary_restrictions: [String],
    gift_interests: [String],
    communication_style: String,
    last_gift_given: Mixed
  },
  interaction_history: [
    {
      date: Date,
      type: String,               -- "meeting", "email", "social", "gift"
      source: String,

    }

  last_contact: Date,
  contact_frequency_days: Number, -- computed average
  importance_score: Number,       -- 0-1

  updated_at: Date

### Collection: user_decisions
{

    selected_option_id: String,
    confirmed_at: Date,
    was_followed_through: Boolean

### Collection: alert_log
{
  _id: ObjectId,

  title: String,

    {
      label: String,

    }

  delivery_channel: String,       -- "push", "in_app", "email"
```

## 5. Arize Phoenix Trace Schema

```
Trace: {
  trace_id: String,
  user_id: String,
  timestamp: Date,
  trace_type: String,           -- "query", "brief", "pattern_alert", "self_improvement"
  
  -- Input
  user_input: {
    query: String,
    context: Mixed,
    source: String               -- "user_typed", "scheduled_brief", "system_detected"
  },
  
  -- Retrieval (what data was fetched)
  retrieval: {
    elasticsearch_queries: [String],
    bigquery_queries: [String],
    mongodb_queries: [String],
    retrieved_documents: [
      {
        source: String,
        document_id: String,
        relevance_score: Number,
        snippet: String
      }
    ],
    retrieval_latency_ms: Number
  },
  
  -- Reasoning (what Gemini produced)
  reasoning: {
    llm_model: String,
    raw_prompt: String,          -- truncated
    raw_response: String,        -- truncated
    structured_options: [
      {
        id: String,
        label: String,
        confidence: Number
      }
    ],
    reasoning_steps: [String],   -- COT traces
    reasoning_latency_ms: Number,
    token_usage: {
      prompt_tokens: Number,
      response_tokens: Number,
      total_tokens: Number
    }
  },
  
  -- Action (what user did)
  user_action: {
    action_taken: String,        -- "accepted", "rejected", "ignored", "modified"
    selected_option: String,
    action_execution_result: {
      status: String,            -- "success", "failed", "partial"
      details: Mixed,
      error_message: String
    },
    user_feedback: {
      rating: Number,            -- 1-5, if provided
      comment: String
    }
  },
  
  -- Outcome (observed later)
  observed_outcome: {
    was_followed_through: Boolean,
    outcome_measurement: Mixed,
    outcome_quality: Number,     -- 1-5, computed
    observation_date: Date
  },
  
  -- Evaluation
  evaluation: {
    relevance_score: Number,
    helpfulness_score: Number,
    safety_score: Number,
    hallucination_detected: Boolean,
    overall_quality: Number      -- composite 1-5
  },
  
  spans: [                       -- for detailed tracing
    {
      span_id: String,
      parent_span_id: String,
      span_type: String,
      start_time: Date,
      end_time: Date,
      metadata: Mixed
    }
  ]
}
```

## 6. Data Relationships

```
USER ──1:N──> CONNECTORS           (users → data_connectors)
USER ──1:N──> RAW_EVENTS           (users → fivetran_* tables)
USER ──1:N──> DAILY_SUMMARIES      (users → enriched.daily_user_summary)
USER ──1:N──> PATTERNS             (users → user_patterns)
USER ──1:N──> MEMORIES             (users → user_memories)
USER ──1:N──> RELATIONSHIPS        (users → user_relationships)
USER ──1:N──> DECISIONS            (users → user_decisions)
USER ──1:N──> ALERTS              (users → alert_log)
USER ──1:N──> TRACES              (users → Arize Phoenix traces)
DECISIONS ──1:1──> TRACES          (user_decisions → traces)
PATTERNS ──N:M──> RAW_EVENTS      (patterns triggered by events)
MEMORIES ──N:M──> TRACES          (memories → trace_ids)
```
